# Claude Remote control: предоставленные скриншоты

Добавлено: 2026-11-01. Источник — два старых скриншота пользователя из телефонной
Remote control сессии Claude Code. Версия приложения и дата самой сессии не
установлены. Это исторический визуальный референс отдельного режима, не запись
нынешней веб-версии обычного чата.

Отдельной формы «создать исследователя и рецензента» на этих кадрах нет.
Это не доказательство отсутствия других экранов или субагентов в приложении.

## Связь со статическими находками APK

В APK ранее найдены CodeRemoteBottomSheetDestination.BackgroundTasksDetail и
BackgroundShellOutput. Ссылка 1 running task и сводка Background shell failed
на скриншотах согласуются с наличием деталей фоновой работы, но прямой переход
между показанным элементом и конкретным destination пока не прослежен.

Subagents / Teammates / Other sessions из другого участка APK нельзя смешивать
с количеством фоновых shell-задач. Субагент, shell-процесс, инструмент и сессия
должны различаться в модели событий.

## Следствия для исправления нашего интерфейса

1. Для режима удалённой работы ориентиром являются реальные события в ленте:
   текст → сводка действия → следующий текст. Не отдельная неподтверждённая
   стартовая форма с фиксированными ролями.
2. Сводки объединяют связанные действия и отображают реальный статус; ошибка
   выделяется у конкретной операции. Успешные и неуспешные события не должны
   автоматически получать одинаковую зелёную галочку.
3. Во время выполнения нужен краткий статус и количество действительных
   фоновых задач. Ссылка может служить входом в детали уже существующей работы;
   её точное поведение требуется проверить перед переносом.
4. Нужно проверить текущую блокировку composer и поддержку обратной связи во
   время работы. Простая смена placeholder на Queue feedback не реализует очередь.
   Контракт доставки следует выяснить отдельно и обеспечить на мосту и телефоне.
5. Селектор модели, настройка разрешений и Stop относятся к текущей сессии.
   Скриншот не обосновывает автоматическое включение обхода проверок в нашем CLI.
6. Не добавлять карточки выдуманных субагентов и не приравнивать running task
   к конкретному исполнителю без соответствующего события из backend.

## Что проверить дальше

- [ ] Раскрытие сводки инструментов: список операций, статусы, вывод, diff.
- [ ] Нажатие на 1 running task: список задач, детали, остановка конкретной задачи.
- [ ] Доступный способ запуска дочернего агента в реальной Claude Code сессии
  и вид событий, поступающих на телефон.
- [ ] Какие поля отличают дочернего агента от background shell в клиентской модели.
- [ ] Ввод и отправка Queue feedback во время обработки, порядок нескольких
  сообщений, отмена, доставка после reconnect и перезапуск клиента.
- [ ] Действие общего Stop при нескольких инструментах/фоновых задачах.
- [ ] Полная подпись режима разрешений и его меню, без предположений по обрезке.

Код проекта этим документированием не менялся. Скриншоты подтверждают видимое
представление событий Remote control, но не серверную реализацию делегирования.
