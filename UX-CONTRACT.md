# Поведение Antigravity Android

Пользовательский контракт: объединить функции локальных ChatGPT и Claude;
специфичные функции телефона и PC-Bridge сохранить в общей системе навигации.
Русский интерфейс, Android Compose. Внешние серверные функции нельзя объявлять
работающими только по наличию строки или класса в APK.

Настройки: AppSettingsScreen владеет главным списком и вложенными страницами.
Back из подробностей возвращает в список; Back/закрытие из списка — в чат.
Существующие параметры сохраняются автоматически через ViewModel. Ключ скрыт по
умолчанию; результат проверки не показывается для другого введённого ключа.
Разрешения открывают существующий AiPermissionsSheet. Статус ПК берётся из
реального результата проверки соединения. Сброс или удаление данных не добавлены.
Поиск настроек выполняется локально по названиям разделов и параметров. Результат
открывает существующую страницу, очищает запрос и снимает фокус с поля; отсутствие
совпадений оставляет поле и действие очистки доступными. Ключи и значения профиля
не индексируются.
Поиск открывается кнопкой в шапке. В корне карточка профиля и строки с иконками
повторяют иерархию живого Claude; длинные пояснения доступны во вложенных страницах.
Шапка пустого чата содержит меню навигации, «Чат/Работа» и меню беседы. Заполненная
беседа показывает название, место выполнения и модель, новый чат и меню;
нажатие на название/модель открывает выбор модели. Контекст, поиск и содержание
доступны в меню; счётчик контекста не занимает постоянную строку. Пустая беседа не содержит придуманного
приветствия. В drawer действие «Новый чат» закреплено снизу рядом с настройками.

Внешний вид: три размера текста и два шрифта ответов применяются сразу, включая
существующие сообщения. Предпросмотр использует тот же MarkdownRenderer, что чат.
Размер меняет также заголовки и код; код остаётся моноширинным, шрифт сообщений
пользователя и интерфейса не заменяется шрифтом ответов. Выбор сохраняется в
SharedPreferences. Отсутствующие или неизвестные значения восстанавливают прежний
средний размер и шрифт с засечками для ответов (изменение по живым референсам
2026-11-04). Явно сохранённый выбор системного шрифта сохраняется.
Содержимое сообщений не меняется. Инлайн-код переносится отдельными чипами;
длинный токен переносится внутри чипа без вставок в исходный текст.

Профиль использует существующие действия Google/веб-сессии. Уведомления показывают
актуальное разрешение Android и открывают системные настройки; статус обновляется
при возвращении в приложение. Обе страницы доступны из корня и поиска настроек.

| Возможность | Единственный владелец | Состояние и восстановление | Проверка |
|---|---|---|---|
| Навигация и история | ChatGptExactNavigationDrawer → ChatHistoryDrawer | Поиск и вкладка архива сохраняются при пересоздании UI; системный Back закрывает drawer | UI эмулятора |
| Поиск | ChatLibrary.search / visible | Названия, сообщения, имена вложений; пустой результат не скрывает поиск | ChatLibraryTest |
| Закрепление, название, архив | AntigravityViewModel.chatLibraryPreferences | SharedPreferences на устройстве; синхронизация transcript не сбрасывает настройки | ChatLibraryTest + UI |
| Отправка / повтор / правка | AntigravityViewModel + ChatHistoryPolicy | Отмена предыдущего хода; сохранение вложений; отдельная ветка | ChatHistoryPolicyTest |
| Черновик | AntigravityViewModel.composerDraft | Отдельный текст для каждой сессии | UI эмулятора |
| Код | MarkdownRenderer → CodeArtifactViewer | Полноэкранное чтение, выделение, копирование, перенос; Back возвращает в чат | UI эмулятора |
| Сохранение файла | ViewModel → PhoneResourceController | Успех только по результату сохранения; кнопка просмотра не заявляет успех заранее | Проверка кода + UI |

Архив не удаляет сообщения и не меняет сервер ПК. Это локальная организация
истории, раскрытая в интерфейсе. Подключение к реальному аккаунту и публикация
артефактов требуют соответствующих серверных интеграций; локальный просмотр кода
не обозначается как исполнение или публикация приложения.

## Сохранённые документы

`ArtifactLibrary` кодирует только локальные сохранённые копии ответов;
`AntigravityViewModel.artifactsLibrary` объединяет их с документами ПК.
Сохранение того же сообщения заменяет копию по стабильному ID, а не создаёт
дубликат. Потоковый незавершённый ответ не сохраняется.
`ArtifactLibraryScreen` владеет поиском, фильтром сохранённых ответов и переходом
список → документ → список. Системный Back из документа возвращает в список.
Удаление доступно только для локальной копии и требует подтверждения; исходный
чат и документы ПК не удаляются. Экспорт использует существующее сохранение
файлов, код открывается через общий CodeArtifactViewer.

Редактирование и версии: заголовок и содержимое локальной копии правятся в
карточке документа; прежний текст сохраняется как версия (до 20), восстановление
версии не разрушительно (текущий текст предварительно уходит в историю).
Повторное сохранение того же ответа объединяется по стабильному ID без дублей.
Документы ПК не редактируются. Интерактивный предпросмотр: Markdown
рендерится, HTML-артефакты открываются WebView-предпросмотром; переключатель
«Предпросмотр/Исходник» всегда доступен. Back из правки возвращает в просмотр.

Синхронизация с ПК (`/api/sync/state`): названия, закрепления, архив и
сохранённые ответы дублируются на ПК и сливаются правилом «побеждает более
новый updatedAtMs»; удаления — надгробиями. Метка времени названия меняется
только при изменении содержимого, чтобы открытие чата не перетирало правки
с другой стороны. Недоступность моста не теряет локальные изменения.

Голос: «Проверить микрофон» выполняет реальную запись и сообщает уровни
сигнала; отказ разрешения и тишина различаются. Речь пользователя прерывает
и озвучку, и текущую генерацию ответа во всех путях barge-in. Диктовка
останавливается с явной ошибкой при фатальных сбоях распознавания (без
бесконечного тихого повтора). Обрыв живого WebSocket переподключается с
экспоненциальной паузой и видимым статусом «Переподключение…», пока звонок
не завершён пользователем.

Серверные функции: генерация изображений выполняется реальным OpenRouter API
(без ключа — явная ошибка; видео не заявляется), сжатие контекста сводит
старшие сообщения реальной моделью и сохраняет локальную историю, Google
Drive работает через настоящий REST API v3 с OAuth; без учётных данных
функции честно недоступны, имитаций успеха нет.

Работа без сети и ошибки: после реальной проверки связи недоступный мост ПК
показывается баннером с кнопкой «Повторить»; стартовое состояние не заявляет
подключение заранее. Сетевые сбои отправки классифицируются и сообщаются
честно, частично полученный ответ и переписка сохраняются. Режим телефона
работает без моста.

## Рабочие области проектов

`ProjectWorkspace` (инструкции проекта, документы контекста, связанные чаты)
хранится на телефоне (`project_workspaces`) и не изменяется синхронизацией
списка проектов ПК. Рабочая область создаётся при первом открытии проекта.
Инструкции и документы входят в контекст запросов модели только для связанных
чатов (включая голосовые); без них запрос не изменяется. Чат принадлежит
одному проекту: привязка снимает прежнюю. Добавление документа читает файл
системным выбором (до 16 МБ); удаление убирает только копию из контекста.
`ProjectWorkspaceScreen` владеет переходами список → проект → список; Back
возвращает к списку проектов.

## Повторная синхронизация

Неудачная отправка не подтверждает сохранение на ПК и не удаляет локальные
данные. Повтор с экспоненциальной паузой до 30 секунд использует текущее
состояние. Удаление с равной меткой времени побеждает устаревшую запись;
метки удаления не истекают до появления более новой живой записи.
Мост подтверждает состояние только после успешной замены файла на диске.

## Задачи телефона и ПК

Основной сценарий — запрос в переписке и реальные события инструментов. Место
исполнения отделено от UI. В режиме телефона модель вызывается напрямую через
настроенный API; мост не обнаруживается, вложения на ПК не отправляются.
Отсутствующий ключ и модель CLI, которой требуется ПК, сообщаются явно без подмены.
Локальная работа инструментов не означает локальный inference модели на устройстве.

Ведущая модель телефона может запросить delegate_task с явной задачей и именем.
Дочерний контекст отделён от родительской истории. До двух подзадач за ход, без
рекурсии; дочернему исполнителю разрешены только read_file/list_dir/search_files/
search_media. Ведущий ход ограничен шестью шагами, дочерний — тремя, до четырёх
запросов инструментов на шаг. Это собственная политика ограничения исполнения,
а не реконструированный сервер Claude. Разрешения Android-инструментов сохраняются.

ToolCallEvent связывает событие с родителем и местом выполнения. Начальный текст
действия, статус и результаты хранятся вместе с чатом на телефоне. После рестарта
незавершённые события показываются прерванными, а не возобновляются автоматически.
Остановка хода отменяет модельные вызовы и помечает видимые выполнявшиеся события
остановленными; уже совершённые изменения файлов не откатываются автоматически.

BackgroundTasksDetailContent показывает задачи текущего разговора. Формы ручного
запуска пары агентов в нём нет. Ошибки инструмента не показываются успешными.
Legacy CLI-пакеты дополнительно привязаны к исходному чату и используют requestId.
При settling=true завершение их review ещё ожидается. Git-копии автоматически
не удаляются; применение изменений требует отдельного реализованного сценария.

## Очередь обратной связи

Во время выполнения текст и вложения можно добавить в очередь, сохранив Stop.
До десяти сообщений на разговор; очередь разделена по chat ID и месту исполнения.
После успешного хода следующий запрос отправляется автоматически только если
пользователь остался в том же разговоре. После ошибки/Stop очередь остаётся для
ручной отправки либо удаления. Голосовой сценарий сохраняет существующее прерывание.
После перезапуска очередь восстанавливается без автоматических платных вызовов.
Временные элементы не пишутся в prefs. Доставка в историю использует стабильный
message ID и предшествует удалению сохранённого намерения из очереди.
Это явно выбранная семантика нашей адаптации: скриншот Queue feedback подтверждает
наличие ввода во время работы, но не точный протокол доставки оригинала.

## Версии сообщений

Редактирование и повтор сохраняют прежнее продолжение внутри того же разговора.
Стрелки и счётчик версий находятся у сообщения пользователя; переключение
восстанавливает соответствующие ответы и вложения без вызова модели. Во время
генерации переключение запрещено. Архив версий сохраняется локально; плоская
история сервера не перезаписывает его. Очередь привязана также к выбранной версии.
Основание редактирования — наблюдение Claude web; точная семантика повторного
ответа является адаптацией проекта, а не подтверждённой копией оригинала.
