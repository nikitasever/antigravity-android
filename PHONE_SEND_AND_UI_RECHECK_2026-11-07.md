# Отправка с телефона и два экрана — 07.11.2026

## Подтверждённые дефекты и изменения

1. `callDirectOpenRouterApi` скрывал HTTP-ошибки и отдавал null. В результате
   401/402/429 были похожи на обрыв соединения. Теперь `DirectOpenRouterChatClient`
   различает аутентификацию, баланс, лимит, недоступность модели, ошибочный JSON
   и error-envelope внутри HTTP 200. Сообщения приложения не включают сырые
   ответы провайдера, ключ или текст запроса.
2. Убирался префикс `openrouter/`. Это часть настоящих ID, например
   `openrouter/auto`; теперь точный выбранный ID передаётся без подмены.
3. Текстовый POST не следует redirects и не повторяется автоматически. Общий
   timeout 240 секунд, ограничение ответа 4096 токенов. Это ограничение может
   оказаться недостаточным для некоторых длинных reasoning-ответов: исчерпание
   лимита без готового текста теперь объясняется явно.
4. Удалены выдуманные 14 ток/с и 320 мс в прямом текстовом ответе. Число токенов
   берётся из API; отсутствие usage не заменяется оценкой, выдаваемой за измерение.
5. Для подтверждённых моделей специализированного image/video API обычная
   отправка использует существующий media pipeline. Универсальная модель с
   текстовым выводом не становится платным генератором только из-за способности
   выводить изображения/видео. Имя модели не используется для выбора API.
   Placeholder и отправка используют один `openRouterComposerRoute`.
6. Неподдерживаемые reference-вложения в генерации не игнорируются и не удаляются;
   сохраняется черновик с пояснением. Ошибка временного чата больше не обещает
   сохранение переписки в историю.

## Границы проверки

Точная причина сбоя на телефоне пользователя пока не установлена: на приложенных
скриншотах нет отправленного запроса, выбранного в чате ID или текста ошибки.
Нельзя утверждать, что именно обнаруженные ошибки были его причиной.

Прямая генерация изображений без ПК всё ещё отсутствует: существующий image
pipeline использует PC-Bridge. Прямое видео реализовано ранее, его восстановление
проверялось отдельно. Смешанный text+image ответ чат-модели пока не преобразуется
в локальное вложение. Ни тест качества коммерческого изображения/видео, ни новая
платная проверка реальным ключом в этом проходе не проводились.

Публикация общего релиза остаётся закрыта незавершённой аутентификацией PC-Bridge
(см. `RELEASE_2_3_0_GATE.md`). Прототип BridgeAccess сам по себе маршруты не защищает.
APK этой проверки — локальная Debug-сборка; подпись отличается от GitHub CI 2.2.0.
Удаление приложения или очистка пользовательских данных не выполнялись.

Протокол запроса сверялся с [официальным API reference OpenRouter](https://openrouter.ai/docs/api_reference/overview).
Различие Image API и изображений через чат описано в [официальном каталоге](https://openrouter.ai/collections/image-models/).
