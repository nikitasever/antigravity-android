## Объём

Проверены связи между MainActivity, ViewModel, сетевым клиентом, моделями,
фоновыми службами, голосом, файловыми инструментами, Compose-экранами,

каждой функции тестами или подтверждённого совпадения с оригинальными приложениями.

## Исправления

- Воспроизведён и устранён `ForegroundServiceDidNotStartInTimeException` после
  отправки сообщения: остановка больше не создаёт службу, foreground включается
  в `onCreate`, ошибки запуска не маскируются обычным уведомлением.
- Отмена закрывает HTTP-соединение, прерывает чтение ответа и отправляет отмену
  конкретного хода на мост. Отменённый запрос не запускает запасной провайдер.
- Поздние ответы и загрузки истории не перезаписывают другой чат. Сервер не
  объединяет независимые запросы по первым 120 символам сообщения.
- Повтор и редактирование сохраняют вложения и предыдущие ходы, создавая отдельную
  ветку. Некорректный ID сообщения больше не приводит к отправке нового запроса.
- История записывается в приватное хранилище через временный файл и атомарную
  замену. Повреждённый файл не мешает восстановлению остальных чатов.
- Черновики, вложения и результаты диктовки относятся к своей сессии.
- Обновление серверной истории сохраняет локальные вложения, идентификаторы,
  инструменты и медиа. Короткий устаревший ответ не обрезает локальную историю.
- Отправленный текст не переписывается эвристиками «повтори» и маркерами старых
  промптов. Сброс контекста действительно исключает прежние сообщения из запроса.
- Запасные прямые API-запросы получают историю диалога.
- Устранена обрезка прикрепляемых файлов до 64–384 КБ. Файлы читаются полностью
  до 16 МБ; превышение лимита явно показывается пользователю.
- Кнопка остановки доступна при наборе следующего сообщения. Системная кнопка
  «Назад» возвращает из внутренних разделов в чат.
- Разрешения больше не расходятся с их копиями после `copy()`. Проверяются
  отключения чтения файлов, контактов, медиа и запуска приложений.
- Обычный блок JSON в ответе не исполняется как инструмент телефона. Для
  инструментального протокола требуется явно обозначенный `phone_action`.
- Исправлены запуск голоса из ярлыка, отказ в разрешении микрофона, освобождение
  распознавателя и фоновых coroutine scope.
- WebView освобождается при уходе с экрана; микрофон доступен только разрешённому
  origin при выданном Android-разрешении. Убрана автоматическая выдача всех ресурсов.
- Исправлены ошибки совместимости с minSdk 26. Отладочные extras, управляющие
  сессиями и инструментами, отключены в release-сборках.
- Чтение stdout Android CLI не блокирует процесс заполненной трубой.
- Мост корректно обрабатывает повреждённый JSON, лимит размера, оборванный запрос
  и UTF-8 между пакетами. Ошибки async-обработчиков не остаются необработанными.
- MCP возвращает ошибки протокола вместо молчания или фиктивного успеха.

## Артефакты: редактирование, версии и интерактивный предпросмотр

Локальные сохранённые копии в ArtifactLibrary теперь редактируемы и версионируются

- Редактирование: заголовок и содержимое сохранённой копии правятся в карточке

  сама версия остаётся в истории. Повторное сохранение ответа с тем же ID

## Синхронизация с ПК: названия, закрепления, архив и библиотека ответов

Настройки чатов (название, закрепление, архив) и сохранённые ответы теперь
синхронизируются с мостом ПК через новые маршруты `GET/POST /api/sync/state`
(`sync-state.json` в pc-bridge). Это реальное хранение на ПК, а не имитация:
при недоступности моста локальные данные сохраняются и досылаются при
следующей синхронизации.

- Слияние детерминированное: по каждой записи побеждает более новый
  `updatedAtMs`; удаления передаются надгробиями `deletedIds[id] = время`.
  Запись новее надгробия воскрешается; надгробие старше записи игнорируется.
- Метка `updatedAtMs` названия/закрепления/архива меняется только при
  изменении содержимого: простое открытие чата не перетирает переименование,
  сделанное на другой стороне; `lastOpenedAt` берётся максимумом.
- Удаление сохранённого ответа ставит надгробие; надгробия старше 30 дней

## Голос: проверка микрофона, прерывания, диктовка и восстановление связи

## Серверные функции: медиа, сжатие контекста и Google Drive

Вместо отключённых имитаций — настоящие реализации; каждая функция либо

## Надёжность синхронизации при отключении

- При неудачном push локальное состояние остаётся на телефоне и отправляется
  повторно с паузой 1→2→4→8→16→30 секунд. Повтор читает актуальное состояние,
  включая изменения, сделанные во время ожидания.
- При равной метке времени удаление имеет приоритет над записью на Android и
  сервере. Отключены удаления tombstones по возрасту: старое offline-устройство
  не должно возвращать удалённый документ через месяц.
- saveSyncState пишет во временный файл и заменяет основной только после
  успешной записи. Ошибка не скрывается: клиент не получает ложный успех.
- Новый Node-тест проверяет равные метки для настроек, артефактов и проектов;
  ещё один проверяет сохранение прежнего файла и ошибку при неудачной замене.

Тесты записи используют временный каталог; рабочий sync-state.json не менялся.

## Субагенты/рой: исправления по SUBAGENTS_RECHECK_AND_FIX.md (раунд 17)

По плану повторной проверки субагентов устранены конкретные дефекты
механизма (без переработки неподтверждённого UI — это отдельное решение).

1. Отменённый или пустой запуск больше не превращается в отчёт в чате.
   `dispatchSwarmTask` вставлял AGENT-сообщение из панели субагентов даже
   после отмены (все статусы cancelled) — в чат попадал фиктивный «отчёт».
   Теперь сообщение добавляется только при наличии real-результата
   (completed/failed с непустым текстом); отменённый запуск показывает
   Toast «Анализ остановлен. Результаты не добавлены в чат».
2. Отмена/тайм-аут теперь останавливают всё дерево процесса, а не только
   прямой child: `subagent-cli` использует `taskkill /pid ... /T /F` на
   Windows (дочерние git/shell удерживают stdio-каналы и не дают `close`).
   Слот исполнителя освобождается по-настоящему, без «остановки по смене
   JSON-статуса». Переполнение вывода тоже грохает дерево.
3. Каталог git-worktree агентов больше не растёт бесконечно: `AgentWorkspace`
   получил `prune()` с ограничением `keep` (по умолчанию 10), вызываемый при
   создании каждой копии. Удаляются только старейшие зарегистрированные
   копии; активное предложение не стирается молча.
4. Поздний result/review не прилипает к отменённому заданию: `SubagentRuntime`
   сохраняет review только у терминальных completed/failed заданий. При этом
   review, полученный при реальной ошибке, по-прежнему показывается — полезная
   деталь после сбоя не теряется.
5. Сервер перед запуском проверяет наличие CLI (`AGY_BIN`); при отсутствии —
   честная ошибка вместо попытки запуска и модели из устаревшего кеша.
6. Исправлены неподтверждённые формулировки: заголовок в
   Round5PanelsAndSheets.kt больше не утверждает «1:1 с Claude»; панель
   описана как наша реализация, навеянная оригиналами, а не их
   воспроизведение.

Новые Node-тесты: killProcessTree (дерево vs child), late-review не
оставляется у cancelled, review реальной ошибки сохраняется, prune ограничивает
копии. Проверка: Node 38 тестов — PASS, Node --check — OK, Android
57 тестов / 0 падений, lintDebug + assembleDebug — BUILD SUCCESSFUL.
