## Подтверждённые исправления кода

1. Изображения: выбранный model ID передаётся без замены по наличию слова image
   в имени. Отправка идёт в POST /api/v1/images с model/prompt/n=1; добавлено
   чтение data[].b64_json. Старые форматы извлечения сохранены для совместимости.
2. MIME/расширение определяются по сигнатуре PNG/JPEG/WebP/GIF; JPEG больше не
   сохраняется как PNG. Неизвестные/пустые данные не выдаются за изображение.
   SVG пока не поддерживается этим обработчиком.
3. Ошибки OpenRouter 400–599 сохраняют свой статус, включая 402/429. Из сообщения
   исключается отражённый API-ключ. Android получает текст ошибки моста вместо
   одного общего HTTP-кода.
4. Категории свежих моделей берутся из input/output metadata и supported_parameters.
   Video input означает понимание, а не генерацию. Название flux/video/sonar само
   по себе не даёт способности генерировать изображения, видео или аудио.
5. Отсутствующая цена не означает бесплатность. Нулевая цена токенов при платном
   image также не означает бесплатность. Android заполняет isImageGen/isVideoGen/
   isVision/isAudio/isReasoning, а не только список categories.
6. Пустые промпт и модель больше не заменяются придуманными значениями. Подписи
   генерации изображения не обещают PNG независимо от фактического формата.
7. Удалено ложное объяснение 501, что у OpenRouter нет видео-моделей. Роут честно
   сообщает об отсутствии интеграции в приложении; сам видео-поток пока не реализован.

Три новые регрессионные проверки сначала упали на старом коде; после исправления
добавлены также тесты MIME, отсутствующей модели и сохранения 402 с маскировкой
ключа. Первую версию тестового extractor исправили: она не сохраняла async при
чтении обработчика из server.js. Итоговые результаты сборки и тестов ниже.

## Что ещё требуется для полного результата

Обновление следующего прохода: объединение трёх каталогов, хранение capabilities,
кэш ПК v2 и прямой Android discovery реализованы и проверены; актуальное состояние
и точные границы — в OPENROUTER_CATALOG_RECHECK_2026-11-07.md. Список ниже описывает
состояние на момент исходного API-аудита.

Следующий проход подключил start/status/download видео через мост и Android-клиент.
Проверки и оставшиеся ограничения — в OPENROUTER_VIDEO_RECHECK_2026-11-07.md.

- Объединить общий каталог с dedicated images/models и videos/models, сохраняя
  возможности и параметры каждого API. Сейчас общий каталог не покрывает все
  доступные генераторы. Обновить старый дисковый кэш: его классификация не меняется
  автоматически от исправления функции для свежего ответа.
- Реализовать video POST → durable job ID → polling → content download; переживать
  перезапуск без повторной платной генерации. Сверять duration/resolution/aspect
  ratio с dedicated capabilities, не навязывать всем моделям H.264/3 секунды.
- Реальная генерация изображений пока не подтверждена: нужен доступный баланс
  для этого медиа-запроса. Проверить также модель, возвращающую WebP/JPEG.
- Проверить Android напрямую без моста: медиа-путь сейчас требует ПК. Сохранение
  файла на телефон, восстановление медиа-задачи, смена чата во время генерации и
  отмена ещё требуют отдельного сквозного сценария.
- Проверить stream/SSE текста, reasoning, tool calling, вложения, 401/403/429,
  timeout и остановку; отдельный успешный HTTP-запрос этого не доказывает.
- Проверить audio/TTS/STT, embeddings и остальные типы отдельно. Категория AUDIO
  пока описывает вход или выход аудио, а не готовность конкретного UI-сценария.

Официальные источники: [Images API](https://openrouter.ai/docs/guides/overview/multimodal/image-generation),
[Videos API](https://openrouter.ai/docs/guides/overview/multimodal/video-generation).
Они подтверждают отдельные API генерации, discovery и асинхронный video job flow.
