# Привязка пачки субагентов к запуску — 7 ноября 2026

## Проблемы и изменение

В AntigravityViewModel dispatch/poll/refresh/cancel читали текущие URL, requestId
и модель из настроек. Backend также выполнял discovery/fallback перед каждым
запросом. После смены адреса запрос мог отправиться другому ПК; запоздалые ответы
записывались в общий список без проверки запуска.

Receiver передавал requestId уведомления, но ViewModel его игнорировал. Старое
«Отменить» могло остановить текущую пачку или телефонную генерацию. Все cancel
PendingIntent имели одну идентичность с UPDATE_CURRENT, новый запуск заменял
extras старого. Receiver сразу закрывал общее уведомление без проверки ответа.

SwarmRunOrigin фиксирует requestId, исходный разговор и URL; модель берётся из
снимка настроек запуска. Это адресация, не токен авторизации. Poll/refresh/cancel
используют зафиксированные значения. Ответ принимается только текущим экземпляром
запуска; batchId должен совпадать либо отсутствовать для старого моста. Старый
finally не снимает признак активности нового запуска.

При непустом requestId запрос идёт напрямую указанному мосту без discovery,
редиректов и автоматического повтора соединения. Public-only сохраняется.
Недоступная задача не переносится на другой сервер. Отмена без requestId не
отправляется. Пустой URL отклоняется в UI.

Отмена из уведомления проверяет ID и не вызывает Stop телефонной генерации.
У каждого запуска свой data URI PendingIntent. Общее уведомление закрывается
после ответа на отмену для текущего запуска. В новом чате отмена инициируется до
смены ID разговора; статусы не подменяются искусственным ready. Результаты
относятся к исходному разговору. Форма запуска и новый экран не добавлялись.

## Проверка и границы

SwarmRunOriginTest проверяет ID отмены, смену запуска с теми же значениями,
чужой batchId, совместимость старого ответа и неполный origin. Два HTTP-теста
поднимают настоящие серверы A/B: GET с 302 и POST cancel с 307 получают ответ A,
запрос/тело/ID проверяются на A, на B — ноль запросов. Модели, CLI и платные API
в этих проверках не используются.

Это не новый прогон Android PendingIntent/BroadcastReceiver или всего ViewModel
в эмуляторе. Отмена из уведомления требует живого владельца задачи в процессе
приложения, как и раньше; долговечный Android worker после уничтожения процесса
не добавлен. Origin не сохраняется на диск. Отключение редиректов означает, что
в настройках нужен конечный адрес моста.

Первый запуск не дошёл до выполнения тестов: JDK HttpServer оказался недоступен
при компиляции Android unit-тестов. Фикстура заменена на обычный ServerSocket;
логи первого запуска сохранены в `uploads/swarm-origin-build.log`.

После замены: **285 unit-тестов, 0 failures/errors/skipped**, включая 6 новых.
HTTP-тесты исполняют настоящий OkHttp-запрос через scopedSwarmCall и проверяют
исходный URL/query/body. Полный ViewModel и Android-уведомления этими тестами
не исполняются. Strict design audit — **0 violations**; `git diff --check` без
ошибок пробелов. Код Node не менялся, Node-тесты повторно не запускались.

Откат не требует миграции данных: изменения адресации ViewModel/backend,
проверки ID и идентичность уведомлений возвращаются вместе. Origin не меняет
