# Задачи на телефоне и ПК: выполненный этап

Дата завершения: 2 ноября 2026.

## Основание адаптации

Пользователь подтвердил общий интерфейс работы на телефоне и компьютере.
Исторические скриншоты Claude Code Remote control используются как референс
представления событий, а не как доказательство локальной серверной архитектуры.
Источник: [CLAUDE_REMOTE_CONTROL_REFERENCE.md](CLAUDE_REMOTE_CONTROL_REFERENCE.md).
Отдельное живое сравнение обычного веб-чата:
[CLAUDE_WEB_REFERENCE_CHECK.md](CLAUDE_WEB_REFERENCE_CHECK.md).

## Что изменено

- Режим PHONE_LOCAL_RESOURCES сразу вызывает телефонный исполнитель. Он не
  обнаруживает мост, не отправляет вложения на ПК и не опрашивает ПК-сессию.
  Модель вызывается существующими прямыми адаптерами Gemini API или OpenRouter.
  Это Android-оркестрация и Android-инструменты с API-inference, не локальный LLM.
- CLI-модели Gemini 4 Argon / Gemini 3.8 не подменяются API-моделью. В режиме
  телефона показано требование выбрать API-модель; отсутствующий ключ тоже
  сообщается явно. Для ПК сохранён существующий CLI-маршрут.
- PhoneAgentEngine обрабатывает реальные phone_action. Ведущая модель может
  запросить delegate_task с именем и отдельным заданием. Результат возвращается
  ведущей модели как наблюдение; фиксированной пары ролей нет.
- Дочерний исполнитель получает отдельный контекст, может только читать через
  read_file/list_dir/search_files/search_media. Запись и вложенное делегирование
  блокируются до вызова Android-инструмента. До двух подзадач на ход; выполнение
  пока последовательное. Границы шагов: 6 ведущему, 3 дочернему, до 4 действий
  из одного ответа. Это ограничения нашей реализации, не правила оригиналов.
- Общая запись ToolCallEvent хранит место выполнения, parentTaskId и текст перед
  действием. В переписке текст может предшествовать сводке инструмента, после
  неё отображается следующий шаг или итог. Детали раскрываются существующей
  карточкой. События и принадлежность сохраняются ChatSessionStore на телефоне.
- Панель теперь показывает реальные задачи текущего разговора. Ручная форма
  «запустить анализ/подготовить изменения» убрана. Legacy PC-worktree routines
  сохранены внутри проекта, но больше не задают основной пользовательский поток.
- Во время агентного текстового хода можно добавить сообщение с вложениями в
  очередь, сохранив Stop. До 10 сообщений на разговор; очередь разделена по чату
  и месту выполнения. После успешного хода следующий запрос отправляется, если
  пользователь остался в нужном разговоре. Ошибка и Stop приостанавливают очередь.
- Очередь сохраняется на телефоне и после перезапуска требует ручной отправки.
  Временные элементы не записываются в prefs. При доставке используется стабильный
  message ID: запись в историю предшествует удалению сохранённого намерения;
  восстановление отфильтровывает уже доставленные записи. Смена remote chat ID
  переносит только очередь соответствующего разговора и места исполнения.
- Stop отличён от ошибки состоянием CANCELLED. Модельные HTTP-вызовы используют
  существующую отмену coroutine/OkHttp. Уже совершённые действия не откатываются;
  мгновенная отмена любой синхронной Android-операции этим не гарантируется.

## Дополнительно исправлен подтверждённый crash

Живой тест мгновенного ответа об отсутствии ключа выявил
ForegroundServiceDidNotStartInTimeException. stopService мог удалить ожидающий
startForegroundService до обязательного перехода в foreground.

Остановка теперь доставляется через lifecycle службы; onCreate сначала выполняет
обязательный startForeground. Желаемое состояние учитывает stop до доставки start
и немедленный запуск следующего хода. stopSelf(startId) и проверка нового запроса
не дают старому stop остановить новую задачу. Повторный живой сценарий из двух
мгновенных ответов прошёл без смены PID/падения.

## Использование установленного Antigravity при разработке

Установлен Antigravity IDE 2.5.5 и доступен agy CLI. Существующий PC-Bridge уже
использует этот CLI; новый remote-control daemon ради проверки не запускался.
Проверен agy models: доступны gemini-3.8-flash-low и gemini-4-argon-high.

По просьбе пользователя узкие задачи разработки делегируются экономно:

1. Один ограниченный результат, точные файлы, критерии готовности и запреты.
2. Минимальный контекст вместо полной переписки; без рекурсивной цепочки агентов.
3. Gemini 3.8 Flash Low для короткой ограниченной задачи. Gemini 4 — при сложности
   или подтверждённой недостаточности результата Flash; не запускать обе на всё.
4. Проверка результата основным агентом по коду, diff и подходящим тестам.
5. Отсутствие замечаний от модели не означает доказанного отсутствия дефектов.

Живой пример: Flash Low, mode plan, sandbox, effort low, timeout 90s, до 200 слов;
только PhoneAgentEngine.kt и FollowUpQueue.kt, без изменений и дополнительных
агентов. Проверялись лимиты, запрет записи/рекурсии, возврат результата и исключение
временных сообщений из сохранения. Модель не сообщила доказуемых дефектов; выводы
сверены с существующими тестами. Вывод текстового CLI не дал полного token usage,
цены не проверялись: измеренную денежную экономию этот прогон не доказывает.

## Ограничения и следующие задачи

Обновление 2.0.2: CLI-модели теперь доступны также для телефонного исполнителя
через существующий PHONE_LOCAL_RESOURCES маршрут моста. Ключ API не нужен;
для модельного ответа нужен ПК. Прямые API-модели по-прежнему обходятся без ПК.
Живой CLI-путь gemini-4-argon-high проверен ответом PHONE_CLI_OK. Версии
сообщений внутри одного разговора уже реализованы в 2.0.1; пункт ниже исторический.

- На эмуляторе нет Gemini/OpenRouter API-ключей. Реальный модельный цикл делегирования
  на телефоне не прогонялся; его логика проверена управляемой моделью и инструментом
  в тестах. Настройка ключа в приложении нужна для живой проверки этого пути.
- Вложения в новом текстовом телефонном пути передают текстовые превью. Изображения
  и аудио не выдаются за проанализированные: нативный multimodal payload — отдельный
  следующий этап.
- Повторные ответы, ветви и история в референсе Claude: реализовать версии внутри
  одного разговора вместо создания нового chat ID при Edit. Это ещё не выполнено.
- Проверить живую очередь при длительном API-ответе, переключении чатов, Stop,
  background/reconnect и на физическом устройстве. UI очереди не является доказанной
  точной копией доставки Queue feedback оригинала; это согласованная адаптация.
- Отдельно проверить очереди медиа-генерации и голосовые прерывания; этот этап
  ограничен агентными текстовыми ходами.
- Проверить полный PC-поток задач и единообразие хронологии событий. Приватный
  протокол Claude и полная OS-изоляция не восстановлены и не заявляются.
