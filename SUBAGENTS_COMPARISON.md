## Что построено здесь

- SubagentRuntime: явный запуск двух независимых анализов, максимум два активных
  процесса, тайм-аут 180 секунд, очередь, отмена, идемпотентный requestId,
  раздельные завершение/ошибка/отмена и ограниченный размер результата.
- Реальный CLI-исполнитель: agy --mode plan --model <selected> --output-format text.
  Флаг dangerously-skip-permissions не передаётся. Изменение файлов и создание
  вложенных агентов не запрашиваются. Plan — политика CLI, не отдельный OS-sandbox;
  параллельное изменение файлов этим этапом не реализовано и не обещается.
- Профили создаются при запуске задачи: исследователь и независимый рецензент.
  Пользовательское создание произвольных ролей и автономное разбиение задач
  главным агентом пока не реализованы.
- Полный жизненный цикл показывается существующим каноническим экраном фоновых
  задач: реальные статусы, модель, задание, результаты и остановка.
- Состояние и результаты сохраняются на ПК. После рестарта незавершённые работы
  обозначаются прерванными; автоматического платного повторного запуска нет.
- Финальный отчёт возвращается в чат. Отдельного третьего вызова модели для
  объединения ответов нет: пользователь видит оба результата без скрытого расхода.

## Что брать из двух приложений

Из ChatGPT — явную ветку разговора, отдельную остановку, сохранение исходной
переписки. Из подтверждённой части Claude — различимые фоновые задачи и просмотр
их результатов. Совмещать следует эти пользовательские сценарии, а не придумывать
неизвестный серверный протокол оригиналов.

Следующий этап для изменения кода агентами: изоляция рабочих копий, выдача прав
по задаче, diff/review перед применением и разрешение конфликтов. Нельзя запускать
несколько пишущих агентов в одной рабочей папке под видом безопасного параллелизма.

## Продолжение: подготовка рабочих копий

Добавлен pc-bridge/lib/agent-workspace.js. Модуль создаёт отдельный detached Git
worktree от зафиксированного HEAD, требует чистый исходный репозиторий и хранение
копий вне проекта. Незакоммиченные изменения не пропускаются молча. Review возвращает
diff отслеживаемых файлов, список новых файлов и признак изменения исходного
репозитория. Пути сверяются с зарегистрированными Git worktrees; автоматического
применения изменений или удаления пользовательских копий нет.

Это подготовительный модуль, пока не подключённый к API и CLI-исполнителю.
Текущие субагенты по-прежнему выполняют только анализ. Git worktree разделяет
рабочие файлы, но не ограничивает доступ процесса к другим каталогам.
Следующий шаг — связать копию с заданием, добавить просмотр новых файлов и diff,
а затем явное применение с проверкой актуальности исходной версии.

Исправлен учёт процессов: тайм-аут завершает статус задачи, но не освобождает
слот исполнителя до окончания его promise. Переполнение stdout также ожидает
закрытия CLI перед освобождением слота. Невыполняющий отмену исполнитель может
удерживать слот; это ограничивает параллелизм вместо запуска лишних процессов.
Проверка: 33 Node-теста, включая настоящий временный Git-репозиторий и worktree;
синтаксическая проверка server.js пройдена. Android-код в этом продолжении не менялся.

## Подключение подготовки изменений

Модуль подключён к server.js через subagent-cli.js. Обычный dispatch_task сохраняет
анализ plan; dispatch_code_task создаёт отдельный worktree для каждого исполнителя
и запускает поддерживаемые установленным agy параметры --mode accept-edits --sandbox.
Флаг обхода разрешений не используется. Это независимые варианты решения, не
автоматическое объединение патчей. Общие Git-метаданные и доступ процесса вне cwd
не изолированы worktree; отдельная OS-изоляция этим не доказана.

Снимок review включает diff от базового HEAD, новые файлы (до 100 превью, до 256 КиБ
на файл и 1 МиБ суммарно; бинарные/слишком большие файлы обозначаются отдельно),
идентификатор копии и sourceChanged на момент окончания проверки. Символические
ссылки не используются для чтения содержимого вне копии. Изменения не применяются.
Android показывает «Подготовить изменения» и открывает «Просмотреть изменения»
через существующий CodeArtifactViewer. Обзор включается в сохраняемый итог чата.

Проверки: 34 Node-теста, 57 Android-тестов, lint и assembleDebug прошли. Статический
premium UI audit strict — 0 замечаний. Интеграционный тест запускает два настоящих
дочерних Node-процесса в двух Git-копиях и проверяет diff/новый файл/неизменность
источника/отказ для грязного проекта. Отдельный живой CLI smoke с Gemini 4 Argon
High действительно заменил note.txt на verified только в тестовой копии, вернул
ожидаемый diff; исходник original остался неизменным. Тестовые файлы:
C:/Users/st811210/AppData/Local/Temp/agent-live-code-YYO0P8.

APK установлен на эмуляторе. Проверено открытие панели, наличие обоих запусков и
отсутствие фиктивного лидера; скриншот verification_screenshots/subagents_panel.png.
При первом запуске был ANR «Application does not have a focused window»; повторный
холодный запуск и проверка панели прошли. Причина ANR этим прогоном не установлена.
Полный Android → production bridge → review-сценарий не подтверждён: работающий
мост по-прежнему требует ручного перезапуска после ранее отклонённой попытки.

Следующее: выбор рабочего Git-проекта, review после изменений исходника, явное
применение выбранного предложения с проверкой конфликтов. Текущий исходный проект
с незакоммиченными изменениями автоматически не коммитится и не очищается.
