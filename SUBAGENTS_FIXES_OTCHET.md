## Что исправлено (конкретные дефекты)

### 1. Отменённый запуск превращался в «отчёт» в чате
- Файл: `app/.../viewmodel/AntigravityViewModel.kt` (`dispatchSwarmTask`).
- Было: после отмены все агенты получали `cancelled`, опрос завершался, из панели
  собирался текст и вставлялось AGENT-сообщение «## Исследователь (cancelled)…».
- Стало: сообщение добавляется в чат только при реальном результате
  (`completed`/`failed` с непустым текстом); отмена показывает Toast
  «Анализ остановлен. Результаты не добавлены в чат».

### 2. Отмена/тайм-аут не останавливали всё дерево процесса
- Файл: `pc-bridge/lib/subagent-cli.js`.
- Было: `child.kill()` убивает только прямой процесс; дочерние git/shell
  удерживают stdio-каналы, `close` не приходит, слот исполнителя зависает.
- Стало: `killProcessTree` — на Windows `taskkill /pid … /T /F`, на POSIX
  SIGKILL; применяется при отмене и при переполнении вывода.

### 3. Каталог git-worktree агентов рос бесконечно
- Файл: `pc-bridge/lib/agent-workspace.js`.
- Добавлен `prune(keep)` (по умолчанию 10): при создании копии удаляются только
  старейшие зарегистрированные worktree; активное предложение не стирается.

### 4. Поздний result/review прилипал к отменённому заданию
- Файл: `pc-bridge/lib/subagent-runtime.js`.
- Стало: review сохраняется только у терминальных `completed`/`failed` заданий;
  у `cancelled` — никогда. Review реальной ошибки у `failed` сохраняется (это
  полезная деталь после сбоя).

### 5. Сервер не проверял доступность CLI перед запуском
- Файл: `pc-bridge/server.js` (`updateMultiAgentSwarmState`).
- Стало: при отсутствии `AGY_BIN` — честная ошибка «CLI Antigravity (agy) не
  доступен на ПК» вместо запуска несуществующего бинарника.

### 6. Мёртвый маршрут «роль лидер» (set_leader)
- Файлы: `AntigravityViewModel.kt`, `MainScreen.kt`, `Round5PanelsAndSheets.kt`.
- Было: `setSwarmLeader` вызывал действие `set_leader`, которого нет на сервере

- Стало: мёртвая проводка удалена (`setSwarmLeader`, `onSetLeader`); `isLeader`

## Дополнение: исправления после независимой проверки

### Сохранность рабочих копий

Автоматическое удаление по возрасту отключено. prune() сохраняет все копии:
без реестра активных заданий и решения о судьбе предложения нельзя безопасно
выбирать их для удаления. Больше нет ни worktree remove --force, ни обходного
fs.rm после отказа Git. Это предотвращение потери данных, а не готовая политика
управления объёмом диска. Ограничение количества копий пока не действует.
Регрессионный тест проверяет сохранность изменённой и заблокированной копии
при создании новой, даже когда превышен прежний лимит.

### Ошибки taskkill

killProcessTree обрабатывает асинхронное событие error и ненулевой код close.
При ошибке вызывается резервная остановка прямого процесса; полная остановка
дерева при этом не объявляется успешной. Повтор error/close не повторяет fallback.
На POSIX по-прежнему гарантируется только попытка остановить прямой процесс.
Тесты проверяют успешный taskkill, исключение spawn, событие error и ненулевой exit.

### Поздний review после тайм-аута

API добавляет settling: задача может уже иметь failed/cancelled, пока процесс
ещё завершает работу и собирает изменения. Этот флаг участвует в swarmActive,
запрете нового запуска и Android isInProgress. Опрос не заканчивается по одному
только failed: итог формируется после завершения executor/review. Поздний review
отменённой задачи по-прежнему не прикрепляется. При загрузке состояния после
рестарта моста settling сбрасывается, чтобы не ждать уже отсутствующий executor.

Добавлен серверный тест последовательности timeout → pending → поздний review →
завершение, а также Android-тесты жизненного цикла failed/cancelled/queued/running.
Предельное время ожидания связи в Android сохранено; при его превышении приложение
показывает сообщение о невозможности получить результат вместо неполного отчёта.

Работающий PC-Bridge этим проходом не перезапускался. Изменения требуют загрузки
нового серверного кода; сквозной прогон через production-мост не заявляется.
